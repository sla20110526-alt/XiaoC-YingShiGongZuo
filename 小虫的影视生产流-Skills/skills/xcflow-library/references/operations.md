# 共享能力库接入操作

首次查询时按相邻总控的 [bindings.json](../../xcflow-control/references/bindings.json) 定位实际库。本系统使用既有 `catalog.json`，`接入索引.json` 只补充运行资源、校验值、是否可选及边界，不另造能力目录或更改专业内容。

## 查询候选

可执行 `python scripts/library.py query` 读取目录，或加 `--domain 导演` 等明确专业筛选。命令从本 Skill 目录运行；从其他位置调用时使用脚本绝对路径。`--model "MiniMax H3"` 仅查装配适配入口。脚本不做专业适用性决策；关键词不足或跨专业需求时读取更广目录，结合任务判断，不能因窄筛选无结果就声称全库没有。

最小目录核查可以先于询问，能力正文读取必须有用户选择。对原入口的候选说明必须补上当前项目任务、具体问题、匹配依据、影响与作用范围，保留准确版本、必要资源、独立依赖、证据和限制。程序的目录匹配不等于专业适用性已通过。

31 张 Profile 中 27 张仍为分析性归纳的初版／受限可选，4 张为《沙丘2》作品 Profile。5 个专业 Skill 保持原版本；《釜山行》1.0 是一个综合条目，内附 Profile 属配套，排除声音。MiniMax H3 官方源文件仍待适配，不能进入可加载候选。

## 准确选版与读取

沿用已有任务信息，不要求用户填写技术表。应用方可以在当前任务临时构造以下选择记录，依据必须对应真实的用户选择或仍有效记录，不能虚构同意：

```json
{
  "project": "沿用项目名称",
  "task": "沿用任务名称",
  "original_unit": "原执行单元",
  "stage": "当前环节",
  "need": "具体问题及期望结果",
  "scope": "本次授权作用范围",
  "selection_basis": "用户准确选择或仍有效选择的依据",
  "capabilities": [{"id": "准确能力标识", "version": "准确版本"}]
}
```

执行 `python scripts/library.py load --selection <选择记录绝对路径>`。这是临时交接数据，不是自动正式登记。返回的是正文与必要资料全文及文件校验值，当前应用方须实际读到需要的内容后才报告已加载；工具输出截断时按返回路径分段读取。需要证据等条件资源时可在该项增加 `resources`，值只能是该版本接入索引登记的库内路径。文件、版本或依赖不符时不自动选择新版或替代项。

对原执行单元交付：能力与准确版本、选择依据、作用范围、实际读取方与结果、正文及资源位置、应用要点、项目依据、预期支持及剩余限制。多个能力分别说明用途，原执行单元按自己的输出约定整合。

27 张早期 Profile 的外部旧库来源字段只作历史追溯，不作为运行依赖；本体已经写明的分析性归纳及证据缺口必须保留。需要更高证据强度时返回专业顾问或建设任务，不自动加载封存旧 Skill。库内原文的旧路由和自动拆镜等指令不覆盖新冻结规范。

## 正式归档与维护

按本岗位冻结流程执行；本只读程序不承担入库批准或写入。建设单元准备候选和验证材料，专业控制部组织用户确认后，由共享能力库岗位在已确认目录实际写入指定版本、目录、来源与校验记录，并同步接入索引。收到材料不等于完成入库。

写前核对准确版本和现有内容。同版本同内容核验沿用；同版本不同内容保留原状并返回冲突。新版本另存，不能改写旧版引用。入库后重新读取每个实际文件和对应目录、来源、校验记录，核对版本及必要依赖，返回保存位置、确认依据、校验结果、实际完成与未完成事项。普通查询和选版不触发这些正式写入。

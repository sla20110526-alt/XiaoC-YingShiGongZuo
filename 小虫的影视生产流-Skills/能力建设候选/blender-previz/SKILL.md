# Blender Previz｜影视镜头预演

本 Skill 是“小虫的影视生产流”的可选专业能力候选。用户通常在分镜与镜头设计完成后，另开项目任务并显式启动本 Skill，只预演其认为容易出问题的一个镜头、几个连续镜头或一段人物动线。不要要求用户提交整场分镜，也不要批量预演未点名镜头。

## 工作目标

把用户的自然语言、局部分镜和实际资产转换为 Blender 可执行配置，直接搭建或修改预演场景并生成结果。用户不需要编写 JSON、Blender Python 或三维模型；JSON 是内部中间格式，常见预演模型由本 Skill 使用 Blender 基础几何搭建，特殊模型按当前镜头需要扩展生成脚本。

验证顺序固定为：

1. 人物站位、起止状态、移动路径、相互距离、朝向和视线。
2. 人物与场景、道具之间的遮挡、穿插、出入画和空间可行性。
3. 构图、景别、机位、焦段、轴线与银幕方向。
4. 摄影机运动、人物运动与镜头时长是否协调。

## 启动与依据

进入具体任务时读取[输入与局部任务约定](references/input-contract.md)和[执行方式](references/execution.md)。先运行 `scripts/check_runtime.py` 核对 Blender、ffmpeg 与预演引擎；实际路径以检查结果为准，不把历史路径当作已绑定。当前架构依据见[GPT-6 Astra 与 Blender 优化依据](references/astra-blender-basis.md)。

只使用当前任务中用户提交或明确指定并实际读取的分镜、资产和文件。新任务不会自动掌握原分镜任务；保留原镜头编号、原准确时长、分镜锚点版本和返回位置。资料足够时直接工作，只询问会改变当前局部预演结果的具体缺口。

## 执行原则

- 用户用自然语言提出要求时，直接转成当前预演配置并执行，不要求用户改 JSON。
- 每次运行生成独立结果目录，不覆盖用户的原始分镜、资产、人工主工程或旧预演结果。
- 常见房间、墙体、门窗、桌椅、台阶、人物代理和简单道具优先用基础几何组合。模型只需达到当前镜头空间验证所需精度，并说明代理程度。
- 已有图片或三维资产时保留真实路径、对象身份、来源和用途；无法可靠导入时使用尺寸明确的代理，并说明未验证的外观或形体部分。
- 技术落地调整可以在本任务内进行，例如把文字站位换算为坐标、调整代理尺寸、修正穿插或实现既定运镜。
- 改变人物行为、镜头叙事任务、镜头顺序、焦段意图、景别意图或时长等创作决定时，不擅自改写分镜；先列明问题和建议，等待用户决定或回到分镜设计更新。
- 用户反馈某处有问题时，只修改受影响镜头段及维持其成立所需的关联内容，然后重新生成和复核。

## 验证与回传

生成后读取[镜头验证](references/validation.md)，同时检查结构化数据和实际预演画面。没有打开或抽帧查看实际结果时，不宣称构图、景别或动线已经验证。

交付时读取[输出与回传](references/output-contract.md)，提供本次局部范围、实际运行结果、发现的问题、已完成的技术修正、需要用户决定的创作事项，以及可读取的 `.blend`、预演视频、关键帧、报告和运行清单位置。

预演视频默认只是摄影机、Blocking、人物动线和节奏参考，不自动代表最终人物外观、场景风格、灯光或材质。需要装配到外部视频模型时，先由用户确认参考用途，并取得实际平台引用名；本地路径不能冒充平台可调用引用。

最终创作结论回到原分镜与镜头设计执行单元整合。本 Skill 不装配最终视频 Prompt，不自动登记资产，不创建其他任务，也不修改22个冻结岗位规范。

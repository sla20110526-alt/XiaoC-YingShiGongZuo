## 一、输出范围

交接中保留目标单元自身的专业能力入口条件，并带入[共享能力调用约定](../通用约定/共享能力调用.md)的准确位置。用户确认需要后，由目标单元在当前任务进入专业控制部选配并回接；分控不替用户选版。视频单元保留既定模型入口：Seedance沿用既有装配，H3仅处理适配且可读的专业Skill，不统一追加大师Profile询问。

按用户指定方式启动：只要求启动部门或执行单元时，默认在当前任务读取对应规范并按该身份承接；要求激活指令时，交付可复制文本；明确要求创建新任务时，在工具支持下创建并写入必要指令、资料或准确引用。未经请求不创建新任务。跨任务读取或传递限于用户明确指定的任务、资料和范围，按实际结果反馈。具体交接字段、读取边界及完成状态见[任务启动与交接约定](../通用约定/任务启动与交接.md)。

影视镜头生产分控 Skill 的用户可见输出分为六类：

1. 目标执行单元推荐
2. 目标执行单元激活指令
3. 任务对话创建结果
4. 必要信息确认
5. Skill 优化事项归类确认

6. 当前任务的目标身份承接结果

每次处理周期根据用户当前请求选择对应输出。

## 二、通用输出原则

### 1. 结果优先

直接呈现当前路由结果、激活结果或归类结果。

### 2. 最小必要

输出仅包含完成本次路由或激活所需的信息。

### 3. 名称准确

完整使用以下执行单元名称：

- 场戏设计综合执行 Skill
- 分镜与镜头设计综合执行 Skill
- 视频生成综合执行 Skill

### 4. 用户指定优先

用户已经指定目标执行单元时，直接输出相应激活结果。

用户尚未指定时，先输出最小必要的执行单元推荐。

### 5. 交接信息忠实

交接内容采用用户回传的既有结果、冻结事项、任务范围和必要引用。

冻结事项以用户明确确认或正式资料明确标注的内容为准。

### 6. 一个目标对应一个激活结果

每个目标执行单元分别对应：

- 当前任务中的明确承接身份及必要依据；或
- 一份独立激活指令；或
- 用户明确要求创建的新任务。

用户同时指定多个执行单元时，按照用户指定分别输出。

## 三、目标执行单元推荐

### 适用请求

用户提供一句话任务目标，并要求分控推荐执行单元。

### 输出内容

- 推荐执行单元
- 推荐理由
- 激活方式选择

### 输出格式

```markdown
推荐执行单元：〔执行单元完整名称〕

推荐理由：〔根据用户的一句话目标，说明该执行单元与当前任务的直接对应关系〕

请选择激活方式：
1. 给我激活指令
2. 创建任务对话
```

用户确认后，按照所选方式输出激活结果。

## 四、目标执行单元激活指令

### 适用请求

用户明确要求：

> 给我“〔目标执行单元〕”激活指令。

### 输出方式

只向用户交付一份完整、可复制的新对话激活指令。

### 基础激活指令格式

```markdown
【〔目标执行单元完整名称〕激活指令】

你现在进入影视镜头生产部的“〔目标执行单元完整名称〕”。

请根据用户将在本对话中提交的具体任务开展工作。

当前任务的信息依据包括：
- 本激活指令明确携带或指向的资料；
- 用户在本对话中提供的内容；
- 当前任务可读取的正式项目资料。

正式工作前，请按照本执行单元自身规定，完成适用于当前任务的专业能力入口确认。

本执行单元发起适用入口并带入任务信息；用户确认需要后，由专业控制部查询共享库并返回候选，用户选定准确版本和必要依赖、实际读取后回到本执行单元，继续当前工作。
```

## 五、携带交接信息的激活指令

### 适用请求

用户主动提供既有结果、冻结事项、任务范围或必要引用，并要求将其带入目标执行单元。

### 插入位置

将“本次交接信息”插入基础激活指令的执行单元身份之后。

### 增量格式

```markdown
本次交接信息：

- 当前目标任务：〔用户提供的目标〕
- 既有有效结果：〔用户回传的结果〕
- 已确认冻结事项：〔用户确认或正式资料标明的事项〕
- 当前任务范围及必要边界：〔用户提供的范围与边界〕
- 必要引用及读取位置：〔用户提供的引用或路径〕
```

用户没有提供内容的字段直接省略，其余部分沿用唯一的基础激活指令模板。

## 六、任务对话创建结果

当前任务承接时，简要说明已实际读取的目标规范及承接范围，随后按目标单元继续工作。以下新任务结果格式只在用户明确要求创建新任务时使用。

### 适用请求

用户明确要求：

> 创建“〔目标执行单元〕”任务对话。

或：

> 开启“〔目标执行单元〕”任务对话。

### 输出内容

- 创建结果
- 目标执行单元名称
- 激活指令写入状态
- 新任务入口

### 创建成功格式

```markdown
已创建“〔目标执行单元完整名称〕”任务对话，并写入激活指令。

请在新任务中提交当前具体任务。
```

由当前 Codex 应用同时呈现新任务入口。

### 创建未完成格式

```markdown
“〔目标执行单元完整名称〕”任务对话创建未完成。

原因：〔可向用户说明的实际原因〕

已为你保留可复制的激活指令：

〔对应的完整激活指令〕
```

## 七、多个执行单元的输出

用户同时指定多个执行单元时：

- 每个执行单元分别生成独立激活指令；或
- 每个执行单元分别创建独立任务对话。

输出顺序按照用户指定的执行单元顺序排列。

每份激活结果明确标注对应的执行单元完整名称。

## 八、必要信息确认

### 1. 缺少目标执行单元

```markdown
请提供目标执行单元。

如尚未确定，请提供一句话任务目标，我将推荐最小必要的目标执行单元。
```

### 2. 缺少激活方式

```markdown
目标执行单元已确认：〔执行单元完整名称〕。

请选择：
1. 给我激活指令
2. 创建任务对话
```

### 3. 用户要求携带交接信息但尚未提供内容

```markdown
请提供需要带入目标执行单元的既有有效结果、冻结事项、任务范围或必要引用。
```

## 九、Skill 优化事项归类确认

### 适用请求

执行单元回传自身岗位职责、专业流程或输出约定问题。

### 输出格式

```markdown
已归类为 Skill 优化事项。

涉及执行单元：〔执行单元完整名称〕
问题类型：〔岗位职责／专业流程／输出约定〕
问题摘要：〔回传问题的简要归纳〕
```

Skill 优化事项归类完成后，本次分控处理结束。

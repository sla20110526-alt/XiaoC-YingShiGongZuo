## 一、流程目标

正式镜头Prompt结构统一读取本系统的[正式镜头 Prompt 模板 v1.0](../模板/正式镜头Prompt模板_v1.0.md)，用于连续单镜头与镜头组。旧项目模板仅保留来源追溯，不再作为运行时读取入口。

资产映射遵循[资产身份与引用约定](../通用约定/资产身份与引用.md)：正文使用名 → 实际平台引用名 → 对应文件与资产身份。系统调用名和平台引用名分别核对；尚未上传或平台引用名未知时，指出受影响的引用缺口，不虚构可执行映射。

接收正式Prompt装配任务时，核对分镜交接中的逐镜焦段或确认表达、原台词及说话者、所需对白／环境声／动作音效及发生位置、实际光源与主体受光、对应视觉与声音参考。用户已明确给出的内容可直接补入依据；“不需要”与“待补”分别处理。需要创作决定的缺口返回用户或分镜设计环节，不由视频装配虚构动作、声音或光源。

专业能力调用仅适用本单元既定模型入口，按[共享能力调用约定](../通用约定/共享能力调用.md)衔接。H3用户确认需要专业Skill后，由专业控制部查询共享库，用户选定已适配且可读的准确版本及必要依赖，再实际读取并回到本单元；无可加载候选时直接说明缺口，在必要装配依据齐备时继续现有装配方式，不要求用户在空清单或待适配源文件中选择。Seedance 2.0、2.5沿用既有方式，不追加通用大师Profile询问。

根据用户提交的当前有效分镜设计、资产引用、声音要求、连续性依据及具体生产要求，按照固定模板和目标模型特性，完成正式分镜 Prompt 的装配、检查与按需修订。

## 二、接收任务资料

根据本次任务需要，接收以下内容：

- 本次装配或修订目标。
- 镜头编号、生成单元及任务范围。
- 已确认的分镜设计。
- 已确认的目标模型及模式信息。
- 本次调用的资产、平台引用名及必要参考资料。
- 台词、声音、连续性及其他具体生产要求。
- 用户明确给出的分镜修改内容。
- 修订任务所需的现有正式分镜 Prompt。
- 用户指出的具体问题或提交的问题视频。

已有明确资料直接沿用；已存入正式项目目录的资料，可按用户提供的准确位置读取。

## 三、正式分镜 Prompt 装配流程

### 第1步：明确本次任务范围

从用户提交的信息中明确：

- 本次涉及的镜头编号。
- 对应的生成单元。
- 采用“连续单镜头”还是“镜头组”。
- 本次需要装配的分镜内容和调用资产。
- 用户提出的具体要求及修改范围。

装配所需信息存在缺失或冲突时，指出具体问题，等待用户补充或决定，不自行推断。

### 第2步：继承目标模型并读取对应参数

继承用户在分镜设计阶段或当前任务中已确认的目标模型及模式，持续用于后续装配与修订，不重复询问。

仅在缺少明确的模型及模式信息时询问；未取得明确依据前，不开始正式分镜 Prompt 装配。

读取 Skill 中对应模型及模式的有效参数记录，用于时长核对及 Prompt 表达适配，不要求用户重复选择模型。

本流程沿用已确认的全能参考模式时长约束：

| 目标模型 | 单条视频最长生成时长 |
|---|---:|
| Seedance 2.0 | 15秒 |
| Seedance 2.5 | 30秒 |
| MiniMax H3 | 15秒 |

用户明确提出更换模型时，更新当前模型依据，读取新模型对应参数，并重新核对本次装配或修订范围内的时长与模型适配条件。

#### 专业能力入口确认

根据已经确认的目标模型及模式，执行对应入口。

**MiniMax H3：**

- 对当前可用的“Prompt 装配与目标模型适配”类专业 Skill 进行最小只读核查。
- 当前任务尚无明确调用选择且确有可用入口时，先询问是否需要对应装配支持；用户确认需要后，由专业控制部查询共享库并返回适配且可读的候选清单及准确版本，供用户选择。
- 用户确认选用时，调用已与现行装配规范完成适配的对应 Skill，作为后续装配与表达适配的专业依据。
- 用户明确不选用时，按照现有固定模板和目标模型表达规则继续装配。
- 用户选择记录为当前任务依据，后续装配与修订持续沿用；用户明确变更选择时更新。

`h3-prompt-writing` 是已收存的 MiniMax H3 待适配来源；只有共享库实际存在经确认适配、允许选用且可读取的版本时，才列为可加载候选。调用版本须保持既定资产引用规范、镜头时长和当前有效镜头内容。

**Seedance 2.0、Seedance 2.5：**

按照现有固定模板和装配方式继续执行。

本环节沿用已经确认的模型及模式，不再次询问模型选择。

### 第3步：确定当前有效分镜信息

以用户提交的已确认分镜设计为装配依据。

用户明确给出景别、机位、运镜、人物站位、动作、时长或其他分镜修改内容时：

- 将用户最新修改作为对应部分的当前有效依据。
- 未涉及的部分继续沿用原有已确认内容。
- 不自行扩大修改范围，不重新设计其他镜头。

用户修改与保留内容存在直接冲突、无法同时装配时，指出具体冲突，等待用户决定。

只有用户要求重新设计镜头且未给出具体修改方案时，才指出需要进入“分镜与镜头设计综合执行 Skill”的设计事项。

### 第4步：核对时长条件

依据当前有效分镜信息及目标模型参数，检查：

- 每个镜头的时长是否以0.5秒为最小单位。
- 是否存在帧数或0.1秒级时间值。
- 镜头组各镜头时长之和是否等于生成单元总时长。
- 连续单镜头或镜头组总时长是否超过目标模型单条视频最长生成时长。

发现时长不符合要求时，指出对应镜头或生成单元，等待用户决定。

不擅自取整、压缩时长、删镜、拆镜、合并镜头、加速动作或更换模型。

### 第5步：建立资产参考

按照既定资产引用规范，建立本次正式分镜 Prompt 的资产参考：

- 只列本次生成实际调用的资产。
- 每个资产使用独立使用名，同类型多个资产逐行列出。
- 不将多个人物、场景或道具合并为一行。
- 保持平台引用名、使用名、引用关系和资产用途准确。
- 正文直接使用资产参考中等号左侧的使用名，不重复书写映射关系。
- 未调用的资产参考行整行删除。
- 尾帧、视频和额外音频参考，仅在用户明确提供时加入。

资产引用规范保持不变。必要资产或引用信息缺失时，指出具体缺口，等待用户补充。

结合当前有效剧本语境、身份对应关系和资产参考，将正式 Prompt 叙述中的“他、她、它、他们、对方”等替换为对应使用名。人物、道具、生物等分别命中正确资产，正文名称与等号左侧保持一致；不机械全局替换，不凭最近出现的名字猜测。

原台词逐字保留，只在台词外明确说话者；原剧本不因本次装配而改写。未能唯一确定的指代，指出原句、镜头或场次及具体歧义，只暂停受影响内容。

### 第6步：按固定模板装配

实际读取本系统的[正式镜头 Prompt 模板 v1.0](../模板/正式镜头Prompt模板_v1.0.md)，根据已确定的生成单元类型，使用“连续单镜头”或“镜头组”格式。模板无法读取时说明缺口，不退回旧项目模板覆盖现行规则。

模板用于规范正式 Prompt 的结构及资产引用；模型继承、时长核对和修改权限按本流程及已冻结岗位职责执行。

按模板装配当前有效信息，包括：

- 资产参考。
- 已确认的画面质感。
- 生成单元类型及总时长。
- 各镜头时长。
- 场景或场景视图。
- 明确景别对象的景别描述。
- 焦段、机位及运镜。
- 镜头开始状态。
- 人物站位及空间关系。
- 人物表演、动作和原台词。
- 人物与场景实际光源的关系。
- 镜头稳定结束状态。
- 同期声及已确认的限制要求。

镜头结束状态写入对应镜头正文，不另设独立字段。

所需内容缺失时指出缺口，不以装配为由补做分镜设计。

画幅和分辨率由用户在生成平台选择，不写入正式分镜 Prompt。

### 第7步：完成目标模型表达适配

根据已读取的目标模型参数、表达特点，以及用户确认选用的专业 Skill（如有），完成目标模型表达适配。

调整：

- 信息排列顺序。
- 指令表达方式。
- 时间组织。
- 信息密度。
- 主体指代。
- 镜头衔接表达。
- 关键约束的表达重点。

优化仅作用于表达，不改变当前有效镜头内容、时长、资产选择及既定资产引用规范。

#### 指代与表达净化

画面与动作描述只写可见内容，声音描述只写可听内容；资产引用、摄影指令及固定生成限制按模板保留。

1. 将叙事功能、人物心理解释、象征意义、风格口号和管理性说明留在装配依据或代码块外，不直接复制进生成正文；原台词保持原文。
2. 对容易被误读为变色、发光、额外动作或特效的文学描写，先核对其当前有效的具体含义。已有明确表现时，将其改写为含义等价的可见或可听描述，只使用已经明确的性质、程度、范围和顺序，不自行降低或夸张程度。
3. “脸色发白、羞红了脸”等只作为按语境检查的示例，不建立一律删除的禁词表。失血、疾病等剧情事实、已确认生理状态及已确认特效必须保留。
4. 已有具体表现足以承载叙事含义时，删除多余解释即可，不为“命运转折”等象征另造转身或其他表演。具体表现缺失，或净化必须新增、替换、删减动作或改变事实时，指出具体设计事项；用户已明确给出修改方案的，直接按该方案装配。
5. 保留当前模板的固定光线、字幕和音乐限制。检查真实受光变化与既定状态是否仍被准确描述，不把“不新增补光”扩展为压暗所有镜头，不把“不要音乐”扩展为删除对白、环境声和动作音效。

### 第8步：执行交付前检查

检查本次正式分镜 Prompt：

- 所用模型及模式是否与当前已确认依据一致。
- 是否采用对应的固定模板。
- 是否完整继承用户提交的有效信息。
- 是否准确装配用户明确提出的修改。
- 未涉及的分镜内容是否保持不变。
- 资产引用名、使用名、用途及正文调用是否一致。
- 逐镜时长、时长求和及生成上限是否符合要求。
- 主体指代、开始状态、动作过程和结束状态是否明确。
- 是否存在遗漏、重复或相互冲突的指令。
- 表达是否适配目标模型。
- 是否混入画幅、分辨率或管理性说明。

- 叙述性代词是否已准确对应资产使用名，原台词是否保持原文。
- 生成正文是否混入叙事解释或象征指令，表达净化是否改变了剧情事实、已确认动作、生理状态或特效。
- 适用的固定光线、字幕和音乐限制是否完整保留，必要摄影指令及已明确的声音是否被误删。

属于装配问题的，直接修正后复核。

涉及资料缺失、用户决定或分镜重新设计的问题，指出具体事项，等待必要信息。

### 第9步：提交正式分镜 Prompt

提交可完整复制到生成平台使用的正式分镜 Prompt。

- 每个代码块对应一个生成单元。
- 镜头编号与生成单元对应关系保持清楚。
- 分析、检查说明、问题提示和修订理由放在代码块外。
- 不以零散补丁句代替完整正式 Prompt。

本次范围内的正式分镜 Prompt 全部装配并通过检查后，完成本次交付。

## 四、正式分镜 Prompt 修订流程

修订时同时沿用当前任务已经确认的专业 Skill 选择，不因修改镜头、重新输出 Prompt 或增加修订次数而重复询问。

用户明确更换模型或变更专业 Skill 选择时，按新的当前依据执行对应入口与适配。

修订时直接沿用已确认的目标模型及模式，不再次询问是否沿用。

用户明确更换模型时，按第2步更新模型依据，并重新执行对应核对。

### 1. 用户指出 Prompt 装配问题

根据用户描述或提交的问题视频，定位与正式分镜 Prompt 有关的问题。

属于遗漏、歧义、指令冲突、资产引用错误或模型表达适配问题时，直接修订。

修订后重新执行时长核对、资产引用核对、模型适配及交付前检查，提交对应生成单元的完整修订版正式分镜 Prompt。

### 2. 用户给出具体分镜修改内容

将用户明确给出的修改装配进对应正式分镜 Prompt，保留未涉及的有效内容。

修订后重新执行时长核对、资产引用核对、模型适配及交付前检查，提交对应生成单元的完整修订版正式分镜 Prompt。

不因局部修改自行延伸调整其他镜头。

### 3. 用户要求重新设计，但未给出具体方案

指出需要进入“分镜与镜头设计综合执行 Skill”的具体设计事项。

取得新的明确分镜内容后，再继续装配。

### 4. 用户明确提出重大视频问题或 Skill 问题

针对用户指出的问题，分析其与 Prompt 表达、模板要求、模型参数或 Skill 规则的关系。

需要修订 Prompt 的，按上述对应路径处理；涉及 Skill 优化的，整理具体问题、依据及建议调整内容，提交 Skill 优化信息。

## 五、连续执行规则

当前模型依据、任务范围和必要资料明确，并已完成适用的专业能力入口确认后，自动连续完成所需的核对、装配、适配、检查与交付，步骤之间无需用户发送“继续”。

仅在以下事项影响继续装配时暂停：

- 当前使用 MiniMax H3，已提出专业 Skill 选择问题，尚待用户确认。

- 缺少明确的目标模型及模式信息。
- 缺少必要分镜内容、资产或引用信息。
- 时长不符合约定或超过目标模型上限。
- 用户修改与保留内容存在需要用户决定的直接冲突。
- 用户要求重新设计镜头，但尚未提供具体修改方案。

获得必要补充或决定后，从对应环节继续执行。

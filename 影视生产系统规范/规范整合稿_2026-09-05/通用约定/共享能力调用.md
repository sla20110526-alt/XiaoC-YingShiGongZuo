# 小虫的影视生产流｜共享能力调用约定

版本：v1.0 正式冻结版。状态：依据用户采用报告第03项建议形成，用户于2026-09-05确认正式冻结。

## 调用路径

**执行单元询问 → 用户确认需求 → 专业控制部查询共享库 → 用户选择 → 加载选定能力 → 原执行单元继续工作。**

使用执行单元已有询问入口，不另建用户窗口或强制新任务。执行单元可做与当前问题有关的最小目录可用性核查；用户确认需要后，在当前任务实际读取[专业控制部规范](../专业控制部/执行流程.md)，按其职责进入选配，再按[共享能力库规范](../共享能力库/执行流程.md)查询。Skill尚未制作或接入时如实说明按规范承接，不能仅凭口头角色名宣称自动Skill调用已部署。

## 入口提供的信息

| 信息 | 内容 |
|---|---|
| 项目与任务 | 已有标识或可辨认名称、原执行单元、当前环节 |
| 需求 | 具体问题、期望产物及希望影响的范围 |
| 有效依据 | 本次相关用户决定、冻结要求、资料、资产及其准确引用 |
| 既有选择 | 已采用能力、准确版本、作用范围及当前是否仍有效 |
| 专项条件 | 涉及时提供目标模型、模式、输出格式或其他必要条件 |

已有信息直接继承，不要求用户重填任务单或补建正式编号；只询问影响候选筛选、版本或实际使用的缺口。

## 专业控制部返回的候选

共享库按任务检索，专业控制部在原入口呈现。每项候选包含名称、类型、可定位能力标识与准确版本、能解决的问题、匹配依据、对当前工作的影响、作用范围、适配与可用情况、必要依赖、限制及已知不确定性。

综合Skill只列一个能力条目，内附Profile、模板和资料按配套资源说明；其他独立Profile／Skill依赖须一并列入用户选择范围，不暗中扩大加载。专业顾问支持可按具体问题与领域提出；涉及已有Skill时同样列明版本，没有对应条目时不虚构库内Skill。

待适配源文件可以单列为储备说明，不能混入可直接加载列表。未找到合适能力时返回查询条件、缺口及影响，不让用户从空清单选择。用户要求全目录时可展开，但仍保留各条目实际状态。

## 选定、读取与回接

用户选择明确到能力、准确版本、范围和必要独立依赖。已有选择在原授权范围内有效时沿用，不自动换成最新版，也不机械重复询问。新范围、冲突或用户变更选择时只处理变化部分。

共享库提供对应版本正文、使用说明及必要模板、参考和依赖；专业控制部或实际应用方须真实读取必要内容。文件不存在、版本不符或依赖不可用时返回具体问题，不私自替换其他版本。

向原执行单元返回：选定能力及准确版本、正文与资源位置、实际读取方及读取结果、作用范围、应用要点、引用项目依据、预期支持结果及仍需处理的限制。多个能力分别明确用途。

“已提供”仅表示正文或位置已经交付；“已读取／已加载”需要实际读到该版本的必要内容；失败或不完整须说明受影响部分。原执行单元在同一任务内应用并完成最终整合，能力内容不覆盖用户决定、冻结事实或该单元职责边界。

用户不需要额外能力，或无合适可用项时，只要必要输入和基础职责足以完成，就继续原执行工作；真实缺口仅暂停相关部分。引用信息随结果保留，只有明确登记请求才进入正式登记。

## 保留的入口条件

- 项目风格锁定：通用方法足够时不提出Profile；需要时只在既有项目风格参考范围选用，不新增专业设计职责。
- 各资产及设计执行单元：沿用自身首次进入、对象变化和授权范围规则；同一有效范围连续工作不重复询问。
- 视频生成综合执行：Seedance 2.0、2.5沿用既定装配方式，不追加通用大师Profile询问。H3仅可选择已适配现行装配规则且实际可读的专业Skill；`h3-prompt-writing`源文件尚待适配时不作为可加载候选。无可用项时说明缺口，必要装配依据齐备则继续现有方式。

共享能力实际目录见[共享能力库](../../../共享能力库/目录.md)。本约定补齐规范接口，不代表新部门Skill已经安装或全链路已经运行验证。

## 一、专业能力候选列表

本次任务信息、候选字段、选定版本读取和原执行单元回接统一遵循[共享能力调用约定](../通用约定/共享能力调用.md)。候选阶段说明必要依赖与适用限制，交付阶段区分已提供、已读取及读取失败；不得把文件位置返回视为已经加载。

根据当前任务查询共享能力库后，向原询问入口返回匹配的候选列表。

| 内容 | 约定 |
|---|---|
| 能力名称与类型 | 明确是大师／作品 Profile、专业 Skill 或专业顾问支持。 |
| 适用问题 | 说明该能力能够帮助当前任务解决什么问题。 |
| 使用影响 | 说明会影响哪些创作判断、工作方法或表达方式。 |
| 本次作用范围 | 明确适用的工作环节、任务或专业问题。 |
| 版本 | 列出可选择的能力版本；专业顾问按领域标识，涉及具体 Skill 时列出对应版本。 |
| 可用情况 | 说明当前接入情况、依据或验证程度，区分可调用能力与仍待接入的资源。 |

清单在当前对话的原询问位置呈现，供用户直接选择。

现有能力不能满足需求时，返回具体能力缺口。影响候选筛选的信息不足时，返回需要补充的具体问题。

## 二、能力加载与交付结果

用户选定能力并完成实际读取后，返回加载结果。

向用户说明：

- 已加载的能力名称与版本。
- 本次使用范围。
- 将如何用于当前工作。

向原执行单元交付：

- 指定版本的能力内容及其来源位置。
- 本次应用要点。
- 需要引用的项目依据。
- 该能力应帮助形成的结果。

选择多个能力时，分别说明各自作用。

沿用已有选择时，明确继续使用的能力与版本。用户明确选择按当前项目要求继续时，返回该选择结果，衔接原执行单元的后续工作。

## 三、专业顾问结果

专业顾问工作完成后，向提出问题的环节返回：

| 内容 | 约定 |
|---|---|
| 专业问题 | 明确本次回答的问题及项目使用场景。 |
| 专业结论 | 给出针对该问题的判断。 |
| 主要依据 | 提供支撑结论的资料来源或可定位引用。 |
| 适用条件 | 说明结论适用的背景、前提和范围。 |
| 创作建议 | 说明该结论如何用于当前创作。 |
| 待核实内容 | 存在不确定性时，说明具体内容及所需补充依据。 |

结论和建议应能对应到具体问题，供原执行单元使用。

## 四、专业能力建设候选

新增或优化能力时，向用户提交可审阅的候选内容，并附以下说明：

- 候选名称、类型，以及属于新增能力还是已有能力更新。
- 拟解决的问题与适用范围。
- 新增或改进的方法。
- 来源与实践依据。
- 相对已有能力的主要变化。
- 已完成的验证及仍待验证的部分。

候选内容按能力类型组织：

| 类型 | 候选内容 |
|---|---|
| 大师／作品 Profile | 创作特点、判断倾向、可参考方法、适用范围及分析依据。 |
| 专业 Skill | 适用条件、所需输入、执行方法、预期输出，以及相关示例或支持材料。 |

从成功镜头制作专业 Skill 时，还应包含：

- 成功镜头及其制作资料的对应引用。
- 用户认可的效果与希望复用的部分。
- 从案例中提炼的可复用步骤。
- 人物、场景、动作等可替换内容。
- 实际制作记录支持的方法，以及分析推导出的待验证方法。

## 五、共享能力入库与更新结果

候选经用户确认并取得共享能力库实际保存、重新读取核验的完成回执后，返回共享能力信息，同时提供回执位置与核验结论：

| 内容 | 约定 |
|---|---|
| 名称与类型 | 明确入库能力及其类型。 |
| 专业分类 | 明确所属能力目录分类。 |
| 版本 | 明确本次形成的共享版本。 |
| 用途与适用入口 | 说明解决什么问题，以及可在哪些工作环节选择。 |
| 可用情况 | 说明当前接入与验证情况。 |
| 内容位置 | 提供能力正文及相关资源的可读取位置。 |

更新已有能力时，同时提供主要变化、适用范围，以及已有项目采用新版本需要调整的内容。

目录更新应与实际保存的能力内容和版本一致，已被项目引用的版本继续保持可读取。

## 六、项目采用与成果引用信息

涉及项目能力采用或专业顾问成果交付时，随相关结果提供：

- 已有项目与任务标识。
- 采用的能力名称、版本及作用范围。
- 专业顾问成果或相关交付内容的可定位引用。

只有明确登记请求时，资料与资产登记部才按既定规范承接登记；平时随结果提供可登记的引用信息。

对话中展示用户选择、判断和继续工作所需的信息；完整能力内容及相关依据供对应执行单元按需读取。

## 一、项目需求对接与能力应用

本次任务信息、候选字段、选定版本读取和原执行单元回接统一遵循[共享能力调用约定](../通用约定/共享能力调用.md)。候选阶段说明必要依赖与适用限制，交付阶段区分已提供、已读取及读取失败；不得把文件位置返回视为已经加载。

首次选择或需要重新选择专业能力时，按以下路径执行：

**执行单元询问 → 用户确认需求 → 专业控制部查询共享库 → 用户选择 → 加载选定能力 → 原执行单元继续工作。**

已有选择仍在有效范围内，且用户没有提出更换要求时，沿用对应能力与版本。

### 1. 承接用户确认的需求

执行单元在既有询问位置询问用户是否需要使用专业能力。

用户确认需要并说明具体要求后，在当前任务实际读取专业控制部的对应Skill；尚未制作或安装时，读取本部门规范按该身份承接，并如实说明承接方式，不宣称Skill已安装或自动调用链已部署。随后按统一约定查询共享库、选版、读取并回到原执行单元。

### 2. 接收当前任务信息

由执行单元随需求带入：

- 项目与当前任务。
- 当前工作环节及承接执行单元。
- 需要解决的专业问题与预期结果。
- 与本次需求有关的已确认要求、资料及资产引用。
- 已有能力选择、版本和作用范围。
- 与需求有关的专项条件，例如目标模型及模式。

优先继承已有信息。存在影响能力选择或使用的具体缺口时，将缺口返回原入口补充。

### 3. 查询共享库并呈现候选

专业控制部根据当前任务，按共享能力库规范查询目录与必要可用性信息，筛选适用候选，在原询问位置向用户呈现清单。

每项候选说明：

- 能力名称与类型。
- 能够解决的问题。
- 对当前工作的主要影响。
- 版本、可用情况及本次作用范围。

用户要求查看全部能力时，展开完整目录；现有能力不能满足需求时，说明具体缺口。

### 4. 根据用户选择加载能力

用户选定 Profile 或专业 Skill 后，实际读取指定版本的能力内容，并向原执行单元明确：

- 选定能力及其版本。
- 本次使用范围。
- 应用要点。
- 需要引用的项目依据。

用户选择多个能力时，分别明确它们在当前任务中的作用。

用户选定专业顾问支持后，进入专业顾问工作流程。

用户选择按当前项目要求继续时，将该选择返回原执行单元。

### 5. 原执行单元继续工作

原执行单元在同一对话中应用已加载的专业能力，继续完成当前项目任务。

随结果提供本次采用的能力、版本和作用范围等可登记引用信息；只有明确登记请求时，才由资料与资产登记部按既定规范执行登记。

## 二、专业顾问工作

### 1. 明确问题与依据

承接用户选定的专业顾问需求，明确需要回答的问题、项目中的使用场景及相关创作要求。

结合入口提供的信息，按需调用资料与资产登记部提供的项目资料，补充必要的专业依据。

### 2. 开展分析与查证

围绕具体问题开展专业分析，核对相关依据，形成结论及适用于当前创作的建议。

对依据不足或仍有争议的内容，说明不确定性、适用限制及需要补充的依据。

### 3. 交回顾问结果

将专业结论、主要依据、适用条件和创作建议交回提出问题的环节。

同时提供结果引用信息；明确要求登记时，由资料与资产登记部按既定规范承接。

## 三、共享能力建设与更新

### 1. 接收建设信息

接收外部专业资源、项目实践经验和用户提交的优化信息，明确希望新增的能力或需要改进的问题。

从项目成功镜头制作专业 Skill 时，用户指出：

- 成功镜头及其项目、镜头编号或可读取位置。
- 具体满意的效果。
- 希望在后续项目中复用的部分。

专业能力建设单元按项目引用读取对应资料：

| 资料 | 读取内容 |
|---|---|
| 成功镜头 | 对应成片，以及各镜头编号或时间段。 |
| 最终制作指令 | 实际使用的最终 Prompt、相关分镜设计及关键创作要求。 |
| 参考素材 | 实际使用的图片、视频、音频，以及顺序和用途。 |
| 生成条件 | 使用的模型、版本、模式及已知设置。 |
| 后期处理 | 对最终效果有贡献的剪辑、调色、变速、合成或声音处理。 |

已有关键修改记录或前后对比时，一并作为方法提炼的依据。影响提炼的具体资料缺口，再向用户补充询问。

### 2. 提炼可复用方法

结合现有能力库，判断适合新增能力还是更新已有能力。

从输入信息中提炼可跨项目使用的方法，明确适用问题、使用条件和预期结果。

对于成功镜头，对照结果与制作依据梳理制作步骤，提取可以复用的方法，将人物、场景、动作等整理为可替换内容。

方法说明应区分实际制作记录支持的内容与分析推导的内容；从单个案例推广出的应用方式，注明仍待其他案例验证的部分。

### 3. 形成候选版本

完成 Profile 整理、专业 Skill 创作、外部资源适配或已有能力优化，形成可供用户审阅的候选内容。

从成功镜头形成的 Skill 候选，应包含适用条件、所需输入、执行方法和成功示例。

核对候选内容与其专业依据、适用入口和预期输出是否一致，说明已完成的验证与仍待验证的部分。

### 4. 提交用户确认

向用户呈现候选内容，并说明：

- 解决的问题。
- 新增或改进的方法。
- 适用范围。
- 来源与实践依据。
- 主要变化及验证情况。

根据用户意见调整候选，经用户确认后形成共享版本。

### 5. 更新共享目录与版本

接收建设单元的候选正文、支持文件、版本与依赖说明及验证结果，依据用户确认发起共享库入库。共享能力库负责正式版本归档和目录、来源、校验记录的实际写入，并重新读取核验；专业控制部据其回执反馈完成情况，不以候选确认或提交代替入库完成。

能力更新时保留项目已经引用的版本，并提供变化说明、适用范围及已有项目采用新版本需要调整的内容。

各项目后续查询共享目录时，可以发现新增或更新的能力，并按用户选择调用。

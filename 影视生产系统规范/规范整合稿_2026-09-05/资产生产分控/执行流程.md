## 一、流程主干

交接中保留目标单元自身的专业能力入口条件，并带入[共享能力调用约定](../通用约定/共享能力调用.md)的准确位置。用户确认需要后，由目标单元在当前任务进入专业控制部选配并回接；分控不替用户选版。视频单元保留既定模型入口：Seedance沿用既有装配，H3仅处理适配且可读的专业Skill，不统一追加大师Profile询问。

启动支持的结果随本次分派简要反馈：目标身份、采用方式、必要资料及其实际到位情况；明确创建新任务时附实际创建结果和任务入口。这是本次操作反馈，不是正式项目进度或资产状态记录。

按用户指定方式启动：只要求启动部门或执行单元时，默认在当前任务读取对应规范并按该身份承接；要求激活指令时，交付可复制文本；明确要求创建新任务时，在工具支持下创建并写入必要指令、资料或准确引用。未经请求不创建新任务。跨任务读取或传递限于用户明确指定的任务、资料和范围，按实际结果反馈。具体交接字段、读取边界及完成状态见[任务启动与交接约定](../通用约定/任务启动与交接.md)。

资产生产分控 Skill 只处理用户提交的以下两类内容：

```text
资产生产分派任务
→ 读取最小资料
→ 确定责任执行单元
→ 核对优先级与已确认生产前提
→ 分别形成目标执行单元激活指令
→ 按指定方式交付文本、在当前任务承接或创建新任务
→ 结束本次分控处理

执行单元 Skill 问题汇总
→ 确认涉及的执行单元和问题范围
→ 归纳为版本优化待核查问题
→ 等待用户决定
→ 停止
```

原任务内的资产修改和返修始终留在原执行单元，不进入资产生产分控流程。

按用户指定方式完成当前任务承接、激活文本交付或新任务创建；已明确授权的启动不再要求用户重复手工提交。

本 Skill 不因完成分派就自行创建后续任务，也不自动感知其他任务内容；明确请求的启动、读取和交接按统一约定执行。

## 二、接收用户提交内容

用户可以向本 Skill 提交：

- 前期准备阶段已经确认的资产资料；
- 首次进入资产生产的任务；
- 新增的补充生产任务；
- 当前执行单元发现的跨执行单元任务；
- 执行单元 Skill 问题汇总；
- 用户对任务范围和分派方式的最新要求。

收到资产生产分派任务后，进入任务分派流程。

收到执行单元 Skill 问题汇总后，进入问题归纳流程。

本 Skill 不要求原执行单元把普通返修内容、资产修改过程或具体生成结果返回分控。

## 三、读取最小资料

处理资产生产分派任务时，只读取完成当前分派所必需的资料：

- 用户当前提交的生产要求；
- 已经确认的资产拆解内容；
- 已经确认的资产类别；
- 已经确认的资产优先级；
- 已经确认的项目风格；
- 用户提供的当前参考资料；
- 已经成立且与当前任务直接有关的生产前提；
- 用户最新决定。

资料已经足以支持任务分派时直接继续，不要求用户重新提供已经明确的信息。

只有缺少会改变责任执行单元、任务范围或生产前提的信息时，才向用户确认该项缺口。

不为分派当前任务读取无关剧本、完整项目资料、其他资产类别资料或全部执行单元内容。

## 四、确定责任执行单元

按照已经确认的资产类别确定责任执行单元：

- 人物资产 → 人物资产制作执行单元；
- 场景空间资产 → 场景资产制作执行单元；
- 道具、器具、机械装置和载具 → 道具与载具资产制作执行单元；
- 生物、怪物和稳定重大形态 → 生物、怪物与形态变体资产制作执行单元；
- 已经确认需要形成独立可复用资产的VFX → VFX资产制作执行单元；
- 需要跨镜头或跨场次复用的角色音色参考 → 角色声音资产制作执行单元。

一个任务包含多个资产类别时，分别拆成多个执行单元任务。

不同执行单元的职责和交接资料分别明确；当前任务可按用户请求切换承接身份，不把多个单元混成一个职责不明的执行者，也不强制每个身份都另建任务。

同一执行单元内没有实际依赖的多个资产，可以根据用户当前任务范围合并为一个批量任务。

资产类别不清或存在责任冲突时，向用户说明具体问题并等待决定，不自行重新分类。

## 五、核对优先级与生产前提

资产优先级和生产前提分别处理：

- 资产优先级只用于当前任务分派的相对顺序；
- 同一优先级内的资产不建立内部排序；
- 不同执行单元中没有实际依赖的任务可以分别分派；
- 同一资产或跨资产存在已经确认的生产前提时，按照该前提安排任务；
- 不根据资产优先级虚构生产依赖；
- 不根据生产依赖擅自修改资产优先级。

发现当前任务缺少已经确认的必要生产前提时，向用户说明具体缺口。

需要由另一执行单元先完成新任务时，为该责任执行单元形成目标执行单元激活指令。

暂不具备生产条件的后续任务保持等待，不把尚不能开始的任务写成可以直接执行的任务。

本 Skill 只使用用户提交的已确认生产前提，不重新设计资产结构，不建立母资产关系或正式版本链。

## 六、形成目标执行单元激活指令

每个责任执行单元分别形成一份能够独立启动的目标执行单元激活指令。

激活指令只携带该执行单元完成当前任务所需的最小资料，不混入其他执行单元职责，也不替执行单元完成资产设计或Prompt编写。

具体组成由输出约定规定。

可以并行的多个执行单元任务，可以在同一轮分别向用户提供多份独立激活指令。

## 七、用户检查与实际分派

提供可供用户检查的任务交接内容；已有明确启动授权时，按用户指定方式执行，不把文本审阅另设为重复启动许可。

用户可以：

- 接受当前任务拆分；
- 修改任务范围；
- 调整本轮需要启动的执行单元；
- 补充资料；
- 要求修正某份激活指令；
- 暂不启动某项任务。

按用户已指定的启动方式执行；默认在当前任务按目标身份承接，索取文本时交付指令，明确创建新任务时在工具支持下创建并写入必要资料。

用户自行创建的任务不自动追踪；由本 Skill 协助创建时，以工具实际结果说明创建和写入情况，不据此认定生产已完成或自动更新正式项目状态。

完成用户当前要求的分控交接或启动支持后，结束本次分控处理；当前任务已切换为执行单元身份时，依其规范继续用户指定工作。

## 八、处理执行单元 Skill 问题汇总

用户回传执行单元 Skill 问题时：

1. 保留用户对问题的原始说明；
2. 确认问题涉及哪个执行单元；
3. 标明问题涉及岗位职责、执行流程、输出约定或实际能力；
4. 标明当前依据来自单次情况、重复出现的问题，还是用户指出的结构性问题；
5. 将其归纳为版本优化待核查问题。

本 Skill 在汇总阶段不直接认定执行单元 Skill 存在版本缺陷。

问题汇总不生成资产返修任务，也不要求原资产离开执行单元。

只有用户明确要求开始修订对应执行单元 Skill 时，才按用户指定方式另行开始 Skill 修订任务。

问题汇总不得自动触发修订、冻结或发布。

## 九、停止边界

出现以下任一情况时，本轮停止：

- 已向用户提供当前要求的全部目标执行单元激活指令；
- 缺少会改变责任执行单元或生产前提的用户决定；
- 已完成执行单元 Skill 问题归纳，等待用户决定是否启动版本优化；
- 用户要求暂停或结束。

停止后不自动进入其他执行单元，不自动开始下一批任务，不自动进行资产登记或正式进度记录。

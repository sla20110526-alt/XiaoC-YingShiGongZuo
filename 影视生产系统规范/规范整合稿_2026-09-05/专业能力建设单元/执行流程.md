# 小虫的影视生产流｜专业能力建设单元｜执行流程

> 正文及冻结来源见[修订依据索引](../修订依据索引.md)，本轮变更见[变更清单](../变更清单.md)。

## 一、承接需求并汇集资料

接收能力建设需求，明确：

- 需要解决的问题。
- 希望新增或优化的能力。
- 希望复用的部分及适用范围。
- 用户已经指定的产物类型和相关要求。

读取外部专业资源、项目案例、顾问方法依据或用户提交的优化信息。

从成功镜头建设能力时，结合用户认可的效果，读取对应成片、最终 Prompt、相关分镜设计、参考素材、生成条件及后期处理信息。

已有资料按引用读取。存在影响建设的具体缺口时，提出补充需求。

## 二、提炼方法并确定建设方式

查询共享能力目录，按需读取与本次需求相关的能力内容。

结合用户要求、实际制作记录和专业依据：

- 提炼可复用的方法及关键步骤。
- 明确方法的适用条件。
- 区分需要保留的核心方法与人物、场景、动作等可替换内容。
- 判断适合新增能力，还是更新已有能力。
- 明确应形成的 Profile、专业 Skill 或配套参考资料。

对于案例中分析推导出的方法，说明现有依据能够支持的范围，以及推广到其他任务时仍需验证的部分。

## 三、制作或优化候选内容

按照确定的建设方式形成候选内容。

| 类型 | 制作内容 |
|---|---|
| 大师／作品 Profile | 创作特点、判断倾向、可参考方法、适用范围及分析依据。 |
| 专业 Skill | 适用入口、所需输入、执行方法、预期输出，以及必要的参考资料和案例。 |
| 配套参考资料 | 与能力使用有关的专业依据、术语说明、案例或其他支持材料，并保留来源信息。 |

引入外部资源时，结合其原有方法和本系统的使用要求完成适配，说明来源及所作调整。

更新已有能力时，围绕本次确认的需求修改相关内容，整理主要变化。

明确候选能力如何衔接既有生产入口、用户选择机制和项目版本使用约定。

## 四、检查并验证候选

核对候选内容与以下信息是否一致：

- 来源与实践依据。
- 适用范围和使用条件。
- 调用方式与所需输入。
- 执行方法和预期输出。
- 引用资料与案例。

根据能力用途开展必要验证，检查候选是否能够按所声明的方式使用，并据此修正具体问题。

记录实际完成的验证、现有资料和案例支持的内容，以及仍需在其他任务中验证的部分。

## 五、提交候选并根据反馈修订

向用户提交可审阅的候选内容，同时说明：

- 解决的问题。
- 新增或改进的方法。
- 适用范围。
- 来源与实践依据。
- 主要变化。
- 验证情况及仍待验证的内容。

根据用户反馈修订候选，并更新相应说明，形成供用户确认的能力版本。

## 六、提交入库并核对结果

1. 整理候选正文、支持文件、版本建议、分类、用途与适用入口、来源、必要依赖、验证情况及主要变化，形成可读取的入库提交材料。
2. 专业控制部根据用户已经确认的候选版本和入库范围发起入库；已有明确确认不重复询问。
3. 共享能力库核对文件、版本、依赖和确认依据，负责归档正式版本及实际写入目录、来源与校验记录。建设单元不代写正式目录或覆盖已归档内容。
4. 同一能力同一版本已存在且内容一致时沿用；内容不一致时由共享库返回冲突，保留原版本，由专业控制部协调修订或新版本确认。
5. 共享能力库重新读取实际保存文件与记录，返回保存位置、版本、目录位置、校验结果和未完成事项。
6. 建设单元核对回执与提交内容一致后报告入库完成；仅提交、仅保存未核验、写入失败或回执缺失时，如实区分状态。

更新已有能力时，建设单元提供变化说明、适用范围及已有项目采用新版本所需调整；共享能力库保留已引用的旧版本，新版本不会自动替换项目当前选择。

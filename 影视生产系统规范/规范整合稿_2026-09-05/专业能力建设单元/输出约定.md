# 小虫的影视生产流｜专业能力建设单元｜输出约定

> 整理日期：2026-09-05。适用系统：小虫的影视生产流。规范稿件，尚未作为新部门Skill安装或完成调用联调。
> 正文及冻结来源见[修订依据索引](../修订依据索引.md)，本轮变更见[变更清单](../变更清单.md)。

## 一、能力建设候选

向用户交付可审阅的候选内容，明确候选名称、类型，以及属于新增能力还是已有能力更新。

按建设类型交付：

| 类型 | 交付内容 |
|---|---|
| 大师／作品 Profile | 创作特点、判断倾向、可参考方法、适用范围及分析依据。 |
| 专业 Skill | 可读取的 Skill 正文及必要的支持文件，明确适用入口、所需输入、执行方法和预期输出。 |
| 配套参考资料 | 与能力使用有关的专业依据、术语说明、案例等内容，保留来源信息，并说明其关联能力和引用方式。 |

候选应包含实际编写或修订的内容，供用户直接审阅。

## 二、候选说明与验证结果

随候选提供：

| 内容 | 约定 |
|---|---|
| 解决的问题 | 说明本次建设针对的具体需求。 |
| 可复用方法 | 说明提炼的方法、关键步骤及可替换内容。 |
| 适用范围 | 明确使用条件、适用任务和对应入口。 |
| 来源与实践依据 | 提供专业资料、外部资源或项目案例的可定位引用。 |
| 主要变化 | 更新已有能力时，说明相对原版本的具体变化；适配外部资源时，说明所作调整。 |
| 验证结果 | 说明实际完成的检查或验证、采用的案例及结果。 |
| 待验证内容 | 明确现有资料和案例尚不能支持的部分，以及推广使用时仍需验证的内容。 |

从成功镜头制作专业 Skill 时，还应说明：

- 用户认可的效果及希望复用的部分。
- 成功镜头与制作资料的对应关系。
- 实际制作记录支持的方法。
- 分析推导出的待验证方法。

## 三、候选修订结果

根据用户反馈修订后，交付更新后的候选内容，并说明：

- 本次处理了哪些反馈。
- 具体调整了什么内容。
- 调整是否影响适用范围、输入、执行方法、输出或调用方式。
- 因本次调整而更新的验证结果及待验证内容。

候选正文、修订说明与验证情况应保持一致，供用户确认。

## 四、共享入库与更新结果

入库前提交：可读取的候选正文及支持文件、版本建议、分类、用途与适用入口、来源、依赖、验证情况、主要变化及用户确认依据。正式归档和目录写入由共享能力库执行。完成结果附共享库回执位置与核验结论；缺少完成回执时说明“已提交，入库待完成”，不得提前宣布共享版本可调用。

候选经用户确认，由专业控制部发起入库，并取得共享能力库实际保存与重新读取核验的完成回执后，返回：

| 内容 | 约定 |
|---|---|
| 能力名称与类型 | 明确本次入库的能力。 |
| 专业分类 | 明确其在共享能力目录中的分类。 |
| 用途与适用入口 | 说明解决的问题及可选择该能力的工作环节。 |
| 可用情况 | 说明当前接入与验证情况。 |
| 共享版本 | 明确本次保存的版本。 |
| 内容位置 | 提供能力正文及相关资源的可读取位置。 |

更新已有能力时，同时提供主要变化、适用范围及已有项目采用新版本需要调整的内容。

目录信息应与实际保存的内容、版本和引用位置一致。项目已经引用的版本继续保持可读取。

## 五、需要补充的信息

存在影响建设或验证的具体缺口时，返回：

- 需要补充的信息或资料。
- 该缺口影响的方法提炼、内容制作或验证事项。

已有项目资料按引用读取，补充问题围绕本次建设的实际缺口提出。

## 六、呈现方式

对话中优先展示候选内容、主要变化、适用范围和验证情况，供用户审阅与确认。

完整能力文件及支持资料通过可读取位置提供。入库完成后，明确返回所保存的共享版本和内容位置。

> 修订及重新冻结日期：2026-09-04。本次修订范围仅限人物与资产指代、生成正文内容范围、表达净化及相应交接和检查条款。
> 本稿为规范稿件，未安装为可执行 Skill。来源基线与修订位置见[修订总览](<D:/Ai影视制作/2026项目/002-2026项目/015-Skill整理/影视生产系统规范/局部修订_2026-09-04_提示词污染与防污染/修订总览.md>)。

## 一、输出原则

以可直接复制到生成平台使用的完整正式分镜 Prompt 为主要交付内容。

根据本次任务，输出对应的正式 Prompt、完整修订版、必要问题说明或 Skill 优化信息，不要求每次交付同时包含所有类型。

正式 Prompt 与说明文字分开，保持生产内容清楚、完整、可复制。

### 专业能力入口确认输出

使用 MiniMax H3，且当前任务尚无明确专业 Skill 选择时，在正式 Prompt 装配前简要输出：

- 当前沿用的目标模型及模式。
- 推荐的专业 Skill。
- 该 Skill 对本次 Prompt 装配与模型适配的作用。
- 是否选用该 Skill 的确认问题。

用户选择后，简要确认采用的装配方式，进入后续执行。

当前任务已有明确选择时，直接沿用；Seedance 2.0、Seedance 2.5 按现有方式装配。

专业能力推荐、选择提示及确认说明放在正式 Prompt 代码块外。正式 Prompt 继续遵守既定模板、资产引用规范和时长约定。

## 二、正式分镜 Prompt 的输出

### 1. 交付标识

每次交付在代码块外简要标明：

- 当前沿用的目标模型及模式。
- 本次生成单元及对应镜头编号。

同批次使用同一模型时，模型信息统一标明一次。这是交付标识，不作为再次询问用户的确认环节。

沿用用户提供的镜头编号及生成单元对应关系。

### 2. 代码块组织

每个生成单元使用一个独立代码块，代码块内为该单元完整的正式分镜 Prompt。

按照固定模板，使用以下对应格式：

- 连续单镜头。
- 镜头组。

同一镜头组内的所有镜头放在同一个代码块内，不将其拆成多个独立交付块。

每个代码块应能独立复制使用，不使用“同上”“沿用前文”等需要用户自行补齐内容的表述。

### 3. 正文内容

按照正式镜头 Prompt 固定模板，装配当前有效的：

- 资产参考。
- 画面质感。
- 生成单元类型及总时长。
- 逐镜时长及镜头内容。
- 场景视图、景别对象、焦段、机位和运镜。
- 开始状态、人物站位、空间关系、表演、动作和原台词。
- 实际光源关系及稳定结束状态。
- 同期声与已确认的限制要求。

镜头结束状态写入对应镜头正文，不另设独立字段。

所有内容以已确认分镜及用户明确修改为依据。必要内容缺失时，输出具体缺口，不用占位符填成正式交付稿。

### 4. 资产引用

资产引用严格沿用既定规范：

- 只列本次生成实际调用的资产。
- 每个资产使用独立使用名，逐行列出。
- 保持平台引用名、使用名、引用关系和用途准确。
- 正文直接使用资产参考中等号左侧的使用名，不重复书写映射关系。
- 未调用的资产参考行整行删除。
- 尾帧、视频和额外音频参考，仅在用户明确提供时加入。

不因目标模型不同而改写资产引用规范。

正式 Prompt 的叙述文字使用资产参考中等号左侧的使用名，不残留指向不清的代词。原台词逐字保留，并在台词外明确说话者；原剧本不作为批量替换后的输出。

### 5. 时长与平台设置

镜头时长以0.5秒为最小单位，不使用帧数或0.1秒级时间值。

镜头组逐镜时长之和必须等于生成单元总时长；生成单元总时长不得超过当前目标模型的单条视频生成上限。

画幅和分辨率不写入正式分镜 Prompt。

### 6. 正文与说明分离

问题分析、检查说明、修改理由和待用户决定的事项，全部放在代码块外。

常规交付直接给出正式 Prompt，不逐项附带内部检查过程。

### 7. 生成内容范围与表达净化

画面与动作描述只写可见内容，声音描述只写可听内容；资产引用、摄影指令及固定生成限制按模板保留。

叙事功能、心理解释、象征意义、创作理由和管理说明不进入正式 Prompt 的叙述正文。原台词保持原文，实际生理状态、剧情事实及已确认特效按当前有效设计保留，不将风险词一律删除，也不新增表演。

必要的表达歧义说明、资料缺口或设计修改事项放在代码块外。常规交付不另附禁词表或逐项净化报告。

### 8. Seedance 2.0 模板的固定生成限制

每个连续单镜头及每个镜头组的完整 Prompt 中均保留以下三段：

```text
光线规则：严格保持场景资产与已确认分镜中的光源、光向和明暗关系。人物、道具和背景不新增正面补光、镜头方向的柔光或额外轮廓光。不为看清人物脸部而提高整体曝光、提亮暗部或削弱阴影。人物脸部可以部分或完全处于阴影中。人物移动与既定光源变化造成的受光变化，按分镜正常呈现。

字幕限制：不要字幕，不将台词转写为画面文字，不添加标题或说明性文字。

音乐限制：不要音乐，不生成背景配乐或情绪铺底音乐。只保留已明确要求的对白、环境声和动作音效。
```

以上限制用于约束生成内容，不表示模型输出已经验证或必然遵从。

## 三、修订版正式分镜 Prompt 的输出

修订交付包含：

1. 代码块外的简短修改说明，标明涉及的镜头或生成单元及本次修改内容。
2. 对应生成单元的完整修订版正式分镜 Prompt。

即使只修改镜头组中的一个镜头，也交付该生成单元的完整 Prompt，保留其中未涉及的有效内容。

不以零散替换句、差异片段或“其余不变”代替完整修订版。未涉及的其他生成单元不重复输出，用户要求完整汇总时除外。

用户明确更换模型后，交付标识与正式 Prompt 同步采用更新后的模型依据。

## 四、暂不能完成装配时的输出

遇到影响装配的资料缺失、引用问题、时长不符或内容冲突时，简要输出：

- 涉及的镜头或生成单元。
- 具体缺失、冲突或不符合要求的内容。
- 需要用户补充的信息或作出的决定。

时长问题应写明相关时长、求和结果或模型上限，让用户能够直接判断问题所在。

指代不清或文学描写无法按现有依据等价净化时，说明涉及的原句、镜头或场次、缺少的身份或具体表现，以及需要用户补充或决定的事项。

用户要求重新设计镜头但未给出具体方案时，只指出需要进入“分镜与镜头设计综合执行 Skill”的具体设计事项。

存在影响正式装配的未解决问题时，不将对应内容标为可直接使用的正式 Prompt。

## 五、问题分析与 Skill 优化信息的输出

### 1. 用户反馈或问题视频分析

根据用户指出的问题或提交的问题视频，输出与本次 Prompt 修订有关的必要结论：

- 问题对应的镜头或生成单元。
- 可确认的问题表现。
- 与 Prompt 内容或表达有关的分析结论。
- 对应的修订内容，或仍需用户补充、决定的事项。

区分已确认的问题与待验证的原因，不将推测写成确定结论。

属于装配问题的，分析后交付完整修订版；属于用户已明确给出的分镜修改，直接按修改内容装配并交付。

### 2. Skill 优化信息

仅在用户明确提出重大视频问题或 Skill 问题时，输出对应的 Skill 优化信息，包括：

- 具体问题及依据。
- 涉及的模板要求、模型参数记录或 Skill 条款。
- 建议调整的具体内容。

Skill 优化信息与正式 Prompt 分开，作为待讨论的修改建议，不表述为已经生效的规则。

## 六、交付完成条件

本次范围内的正式分镜 Prompt 已完成装配、通过检查并完整交付后，本次交付完成。

如仍有影响交付的未解决事项，应明确说明对应范围及所需补充，不将其表述为全部完成。

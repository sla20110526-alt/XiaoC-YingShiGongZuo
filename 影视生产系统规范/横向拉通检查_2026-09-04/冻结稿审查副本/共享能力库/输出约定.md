# 共享能力库｜输出约定

**一、统一输出原则**

共享能力库向专业控制部返回查询、交付和维护结果，由专业控制部通过既有入口衔接用户及原执行单元。

输出应对应当前任务、准确标明版本，并区分目录检索、文件提供、实际读取和问题返回等状态。

已有项目标识与格式直接沿用。普通调用只展示本次必要信息，完整能力正文和配套资料按需读取，不要求在回复中全部展开。

**二、候选查询结果**

**1. 任务对应信息**

简要标明本次查询对应的任务、原执行单元、当前工作环节、所需能力及作用范围。

已有明确记录的信息可直接引用，不重复要求用户填写。

**2. 候选列表**

每项候选至少提供：

| 字段 | 内容要求 |
|---|---|
| 能力名称与类型 | 明确属于大师／作品 Profile 或专业 Skill，并标明主要专业方向 |
| 能力标识与版本 | 能准确定位具体条目及版本 |
| 用途与匹配依据 | 说明该能力可支持当前任务的哪些部分，依据哪些已登记条件匹配 |
| 必要依赖 | 说明需要的配套资料及其他独立能力 |
| 限制与不确定项 | 说明适用边界、排除范围、证据限制及待判断问题 |
| 当前状态 | 分别说明适配情况、是否允许选用及已知接入限制 |

综合 Skill 按一个条目展示，可列出关联专业。内附 Profile、模板和参考资料列为配套资料，不重复呈现为独立候选。

匹配依据属于检索说明，不表述为已经完成专业适用性判断。

**3. 无合适候选或信息不足**

明确返回：

- 已依据哪些任务条件进行查询；
- 未找到合适条目，或哪些信息仍不足；
- 缺口影响哪一部分查询或交付。

待适配源文件可作为另行说明的储备资料，不混入可直接加载的候选列表。

**三、选定版本交付结果**

用户已选定能力，或已有选择仍有效时，返回以下内容：

| 字段 | 内容要求 |
|---|---|
| 任务对应信息 | 项目与任务引用、原执行单元、当前工作环节 |
| 选择依据 | 本次用户选择，或仍有效的既有选择记录 |
| 选定能力 | 能力名称、唯一标识、准确版本 |
| 作用范围 | 本次应用的任务、场景、镜头或专业环节 |
| 能力内容与位置 | 提供正文或准确的可读取文件位置 |
| 必要配套资料 | 列明本次所需资料及其与该版本的对应关系 |
| 独立依赖 | 列明已纳入用户选择范围的其他独立能力，如有 |
| 使用边界 | 保留适用限制、排除范围、证据边界和影响交付的条件 |
| 交接信息 | 说明本次提供的能力内容由哪个原执行单元承接 |

交付内容与选定版本保持一致，不混入未选能力或其他版本的内容。

涉及能力自身已有的输入要求、输出要求和检查规则，应随必要内容一并提供，供原执行单元正确应用。

**四、读取与交接状态**

文件已提供与内容已读取分别说明：

- **已提供**：已给出指定版本的文件或正文，但尚无实际读取确认。
- **已读取**：实际读取方已确认选定版本及必要资料读取成功。
- **读取失败或不完整**：说明失败位置、缺失内容及其影响。

不得仅凭目录命中、文件存在或路径已返回，就标记为“已加载”。

交接完成时，明确选定能力、版本、作用范围及承接的原执行单元。加载和交接信息随本次结果提供，沿用既定登记方式，不另建项目成果登记流程。

**五、异常与缺口返回**

遇到版本缺失、停用、依赖不全、内容不一致、读取失败或作用范围冲突时，至少返回：

- 对应任务、能力及版本；
- 具体问题与已有依据；
- 对本次使用的影响；
- 哪些内容已完成，哪些尚未完成；
- 需要专业控制部协调处理的事项。

结果应明确是否能够完成本次指定交付。

不自行用其他能力或版本替换，不将未完成的交付标记为完成，也不直接新增用户询问入口。

**六、入库与维护结果**

完成入库、更新或维护任务后，返回：

| 字段 | 内容要求 |
|---|---|
| 处理对象 | 能力名称、标识、版本及相关文件 |
| 本次操作 | 新入库、版本新增、目录修正、状态更新或问题登记 |
| 分类与来源 | 主分类、关联专业、来源说明及归档位置 |
| 检查结果 | 文件、版本、依赖、引用和目录一致性的检查结果 |
| 确认依据 | 对应的入库、适配、启用或状态变更确认记录 |
| 当前状态 | 明确收存、适配和是否允许选用的实际情况 |
| 影响说明 | 是否涉及既有引用版本，以及需要专业控制部处理的问题 |

原文收存、适配文件与新增说明分别记录来源关系。文件校验信息保存在入库记录中，普通回复按需摘要。

完整性检查通过不表述为专业质量通过、实际效果通过或自动调用入口已部署。

**七、输出边界**

共享能力库输出目录信息、检索依据、指定版本内容、交接信息和维护结果。

最终专业适用性判断、能力修订决定、用户选择以及项目成果制作，分别由既定责任方承担。

所有输出应使接收方能够明确判断：**提供了什么、对应哪个版本、适用于哪里、当前完成到哪一步、后续由谁承接。**

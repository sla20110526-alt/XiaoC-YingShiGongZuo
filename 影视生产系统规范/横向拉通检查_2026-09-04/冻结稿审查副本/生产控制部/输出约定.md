# 生产控制部｜输出约定

**一、统一输出原则**

生产控制部根据本次请求，提供分支归属与启动结果、跨分支交接内容、生产摘要、问题处理建议、服务衔接信息或 Skill 优化信息。

只展开当前任务适用的内容。日常优先说明实际结果、关键缺口和下一承接方，详细依据与完整清单按需提供。

已有项目名称、任务标识、成果引用和版本信息直接沿用。涉及状态判断时，保留必要来源和作用范围。

**二、分支归属与启动结果**

确定或启动目标分控后，至少说明：

| 内容 | 输出要求 |
|---|---|
| 目标分控 | 明确前期准备分控、资产生产分控或影视镜头生产分控 |
| 承接任务 | 本次目标、处理对象及作用范围 |
| 采用依据 | 实际采用的规范或 Skill；涉及 Skill 时标明版本 |
| 实际状态 | 已完成的准备、读取或任务承接 |
| 关键缺口 | 影响启动或继续工作的条件，如有 |
| 下一步 | 由目标分控继续处理的事项 |

依据规范开展工作与正式读取 Skill 分别说明。仅完成准备时，明确准备范围；已经承接任务时，说明当前工作身份和任务范围。

具体执行单元的分派结果，以目标分控实际承接和处理的情况为依据。

需要新对话时，提供可直接使用的激活指令。指令已形成、任务已创建和任务已开始执行，分别依据实际结果表述。

**三、跨生产分支交接内容**

跨分支任务应提供足以让接收方继续工作的必要内容：

| 字段 | 内容要求 |
|---|---|
| 交接目标 | 本次需要接收方完成什么 |
| 提供方与承接方 | 明确相关生产分控及各自责任 |
| 工作范围 | 处理对象、涉及范围和已确认限制 |
| 有效依据 | 实际使用的成果、准确位置、版本及必要确认信息 |
| 预期交付 | 接收方需要返回的成果或处理结果 |
| 缺口与返回条件 | 尚缺资料、影响及需要返回协调的情况 |

共同信息统一说明，不同分支的任务和限制分别列明。

已有正式记录通过准确引用衔接。资料尚未取得或尚未核实时，明确标注，避免接收方误认为已经到位。

交接状态区分：

- 交接内容已准备；
- 用户反馈已转交；
- 工具实际完成传递；
- 已收到承接结果；
- 尚待处理或回传。

仅准备交接内容，不表述为目标分控已经收到或执行任务。

**四、生产摘要与任务恢复信息**

汇总或恢复工作时，根据本次实际取得的信息提供：

- 当前生产目标与汇总范围；
- 涉及的生产分支；
- 已形成的成果及必要引用；
- 当前有效依据、版本和能力选择；
- 进行中事项、关键缺口及待回传内容；
- 下一承接方和下一步工作。

状态应区分内容已形成、用户已确认、正式登记已完成和成果已可使用。

没有取得最新反馈的部分，说明目前掌握的信息范围。存在冲突或有效性存疑时，标明待核实事项。

分别说明本次任务、相关生产分支及本次生产范围的完成情况。项目整体状态由总控结合各部门结果汇总。

用户要求返回总控时，提供必要生产摘要与依据引用，不要求重复提交全部生产资料。

**五、跨分支问题与调整建议**

出现阻塞、冲突、返工或调整需求时，至少说明：

| 内容 | 输出要求 |
|---|---|
| 问题与依据 | 具体表现、来源及涉及版本 |
| 问题性质 | 项目内容、输入引用、依赖、执行结果、Skill 或规范问题；无法确定时标为待诊断 |
| 影响范围 | 涉及哪些任务、成果和生产分支 |
| 责任归属 | 需要哪个分控或责任方处理 |
| 当前处理情况 | 已完成事项和仍未完成的部分 |
| 建议安排 | 后续处理方式、必要交接及需要用户决定的事项 |

原任务内修改、同分支跨单元调整和跨生产分支协调，应明确各自承接位置。

涉及用户决定时，提供具体调整内容、理由及影响。涉及冻结规范修订时，形成问题和拟修改范围，衔接总控。

处理结果以实际回传为依据。修订完成、复核完成和相关任务可以继续，分别说明。

**六、专业支持与资料登记衔接信息**

**1. 专业支持**

需要协调专业控制部时，提供：

- 发生需求的生产任务及原执行位置；
- 所需支持的具体问题与作用范围；
- 已有依据、限制及相关能力选择；
- 对当前生产的影响。

收到支持结果后，说明实际提供的内容、对应版本、适用范围及返回的原任务位置。

候选能力、用户选择和实际读取状态沿用既有调用记录，不把候选推荐表述为已经选用或加载。

**2. 资料与资产登记**

用户要求汇总提交资料或资产时，提供：

- 本次提交范围；
- 已取得的对象、文件及准确位置；
- 必要的对应关系、版本和用户确认信息；
- 缺失或尚待核实的内容。

提交清单已整理、资料已转交和正式登记已完成分别说明。

收到登记或查询结果后，引用实际回执、记录位置及其覆盖范围。

**七、生产体系的 Skill 优化信息**

实际形成优化信息时，至少包含：

- 涉及的生产分支、Skill 和版本；
- 使用场景与问题表现；
- 案例或已有依据；
- 当前判断的问题类型；
- 影响范围，尤其是跨分支影响；
- 期望改善的结果；
- 建议责任方及处理顺序；
- 尚待核实或等待反馈的内容。

已有问题标识直接沿用。重复反馈合并，保留不同案例。

优化信息交付用户，并按需要衔接总控。具体修改与专业验证由相应责任方承担。

依据实际反馈，分别说明建议已提交、修改已完成、验证情况和剩余问题。优化完成不自动改变项目已选版本。

**八、完成与记录表述**

本次请求未全部完成时，分别说明实际完成部分、未完成部分、原因及继续处理所需条件。

“已读取、已加载、已创建、已传递、已保存、已登记、已验证”等表述，应有相应实际结果支持。

生产控制部输出的摘要和交接内容保留必要引用，正式专业成果、项目记录和共享能力版本由相应责任方维护。

本次结果限定于实际处理和核对的生产范围。

## 解决的问题与适用入口

在分镜与镜头设计完成后，由用户另开项目任务并显式启动，只处理其点名的一个疑难镜头、几个连续镜头或一段人物动线。用户提供自然语言、局部分镜和实际资产，执行方负责内部 JSON、Blender Python、代理建模、运行与画面复核。

验证顺序为：人物站位与动线；人物、场景和道具的空间关系；构图、景别、机位、焦段和轴线；摄影机运动与准确时长。它不替代原分镜设计，不批量预演未点名镜头，也不负责最终视频 Prompt 装配。

## 当前限制与待验证内容

- 当前通用配置以基础房间、桌体和人物代理为主；特殊场景与模型仍需按当前镜头扩展生成脚本。
- 当前标准 Blocking 为每个角色一段起终点移动；多节点路线、停顿、转身与速度曲线仍待扩展。
- 当前标准摄影机为固定机位与硬切；轨道、摇移、跟随、变焦和复杂目标约束仍待扩展。
- `.blend`、FBX、glTF 等正式资产的通用导入、尺寸、坐标轴和绑定适配仍需真实项目验证。
- 预演视频默认仅作 `camera_blocking_reference`。本地路径不能冒充外部视频平台的实际引用名；正式 Prompt 仍需用户提供或平台实际可见的引用值。

# 输入与局部任务约定

## 默认任务单位

默认只处理用户点名的疑难范围：一个镜头、几个连续镜头或一段人物动线。完整场戏和全部镜头不是必需输入。仅在当前问题无法脱离相邻状态判断时，补读必要的前后镜头或场戏空间依据。

## 最小输入

- 可辨认的项目、场次或局部任务名称。
- 当前要验证的镜头编号或镜头段。
- 用户提供的分镜设计正文、文件或准确读取位置。
- 本段人物的开始位置、结束位置、关键行动和必要朝向；分镜已有时直接继承。
- 当前场景的可用空间依据；没有精确尺寸时，区分用户已确认值与为了预演建立的暂定尺度。
- 本次希望重点检查的问题。用户未另行指定时，优先检查人物站位与动线。

## 按需输入

- 人物、场景、道具图片或三维文件的真实路径、来源和用途。
- 最新分镜锚点版本及其准确位置。
- 镜头焦段、景别、机位、摄影机运动、画幅、帧率和准确时长。
- 必要的前后镜头起止状态、轴线和银幕方向。
- 预演视频之后是否可能作为外部视频模型的参考，以及希望它只影响哪些方面。

## 自然语言与内部配置

用户不需要编写或维护 JSON。根据实际分镜和用户要求建立内部配置，并在执行前检查：

- 人物、场景、道具名称与真实对象身份一致。
- 原镜头编号、原准确时长和原顺序保持不变。
- 预演本地帧号与原镜头编号有明确映射。
- 推定的空间尺寸、站位坐标或代理形体单独标为预演假设。
- 缺少的创作决定不由 JSON 默认值暗中补齐。

局部预演可以从本地第1帧开始，但必须在运行清单中保存原镜头编号、原时长和本地帧段的对应关系。

## 跨任务边界

新任务只依据用户实际带入或明确指定并读取的资料工作。不得声称自动知道原分镜任务的最新状态。交付时保留原执行单元或用户指定返回位置，方便把确认结果回写到最新分镜锚点。

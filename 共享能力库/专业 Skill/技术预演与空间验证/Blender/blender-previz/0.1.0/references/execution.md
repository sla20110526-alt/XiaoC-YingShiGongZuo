# 执行方式

## 运行入口

当前版本使用本机 Blender Previz Engine。先运行：

```powershell
python scripts/check_runtime.py
```

检查通过后，从用户自然语言和局部分镜建立本次配置，再调用引擎根目录的 `run_previz.py`。使用新的运行编号，禁止覆盖旧运行目录。

```powershell
python <engine-root>/run_previz.py --config <scene.json> --run-id <run-id> --render
```

命令中的实际路径必须来自本次检查或用户提交，不照抄示例占位符。

## 场景搭建

优先复用引擎已经支持的结构。普通预演模型采用满足空间判断的最低必要精度：

- 人物：明确身高、占地、身体朝向和可见正面；需要时增加手臂、腿部或动作代理。
- 场景：建立决定走位、遮挡和机位的墙体、门窗、地面、台阶、通道和高差。
- 道具：建立影响动作、视线、遮挡或构图的体积与位置。
- 摄影机：保留镜头编号、焦段、传感器、位置、目标、开始与结束帧；运镜保留路径和关键帧。

现有通用结构无法表达当前镜头时，修改 Blender 生成脚本或增加项目级模型函数。修改范围只覆盖当前任务需要，并在报告中说明新增能力是否仍属项目特例。

## 迭代

1. 建立或更新内部配置。
2. 先校验字段、引用、时长和输出位置。
3. 在新运行目录生成 Blender 工程和预演。
4. 读取运行清单、结构化场景报告和实际画面。
5. 直接修正实现错误或用户明确要求的变化。
6. 重新运行受影响镜头段。
7. 保留旧运行，标明当前有效运行。

同一反馈不扩展到未点名镜头。若修正会改变已确认分镜创意，先暂停受影响部分并向用户说明。

## 文件安全

- 原始资产和用户主工程只读使用。
- 自动构建从空白或专用模板开始，不对用户人工主工程执行清空场景逻辑。
- 运行结果写入 `runs/<project>/<scene-or-segment>/<run-id>/`。
- 配置、工程、视频和报告通过运行清单绑定；不得仅凭文件名推断版本。
